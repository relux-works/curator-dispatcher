# Unresolved questions

[Dispatcher specification §16](spec/dispatcher.md#16-open-questions) is the authoritative local publication and qualification index. This file provides navigation, not a second status register. An open or unqualified join remains unavailable; documentation review does not qualify it.

For the [minimal non-federated full protected-launch target and dependency gates](spec/dispatcher.md#21-full-protected-launch-target-and-dependency-gates), consult these entries in §16:

- Question 9: purpose-6 custody/allocation, both signing adapters, complete protected typed plans, current protected dispatcher association and bootstrap/proof/replay/rotation. Operator-enrolled bootstrap is also closed. Purpose-2 registrar enrollment is insufficient; registry publication waits for federation.
- Questions 10–11 and 33: full broker grant/revocation/binding/issue/renewal/removal joins and receiver observations; standalone v0 allowlisting cannot substitute for them.
- Questions 11, 13 and 33: user-manager launcher/FD3, journaled stop/account-wide absence, observations/inventory and dispatcher cleanup beyond station v0. An `active` account is not launchable; its operator-only per-act waiver is not delegated to the dispatcher.
- Questions 22, 25 and 33: export/custody/cleanup, host capability/exec gates and exact native qualification. Linux is first in work order; macOS activation requires native qualification, and missing qualification closes either platform.
- Question 33 also distinguishes the proposed reduced launch/lease milestone. Its [DRAFT existing-worker policy/request candidate](spec/m0-launch.md) is pending consumer/independent review, protected installation, first-caller/bootstrap/currentness and native receiver/P7 qualification; launch stays unavailable without an explicit owner-approved, jointly published and qualified limited policy or real broker slice-0 grant/revocation integration. V0 credential leasing does not supply launch authority; full target grant/freshness/binding gates remain intact.

All other §16 prerequisites remain in force. [Bounded positive/negative counterexamples](spec/dispatcher.md#151-bounded-documentation-contract-counterexamples) explain this revision's contract boundaries without claiming executable tests or runtime support.
